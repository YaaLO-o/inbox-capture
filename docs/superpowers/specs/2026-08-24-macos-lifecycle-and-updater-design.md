# INbox macOS 生命周期与应用内更新设计

日期：2026-08-24  
目标版本：1.1.1

## 目标

本次改动解决五个相互关联的问题：

1. 恢复 macOS 原生红黄绿窗口按钮。
2. 修复拖动桌宠时卡顿、抖动和无法准确停在目标位置的问题。
3. 增加菜单栏图标，让窗口关闭后仍能重新显示，并提供明确的完全退出入口。
4. 让后续版本更新由 INbox 发起，并在 App 窗口内显示下载和安装进度。
5. 加固终端一键安装脚本，确保旧实例退出后才原子替换应用，并始终启动 `/Applications/INbox.app`。

首次安装仍由终端显示进度，因为下载期间 INbox 尚未安装和运行。应用内进度仅用于已经安装 INbox 后的后续升级。

## 已确认的根因

### 窗口按钮

`MainFlutterWindow.swift` 在提交 `5d4c777` 中显式隐藏了关闭、最小化和缩放按钮。恢复按钮不需要重新实现 UI，只需停止隐藏系统按钮，并保留标准 macOS 行为。

### 拖动

当前 Flutter 层在每次 `onPanUpdate` 时把局部坐标增量通过 MethodChannel 发送给 AppKit。窗口本身移动后，Flutter 视图的坐标系也随之移动，后续增量会受刚刚发生的窗口位移影响；高频异步通道调用还会累积延迟。这会造成抖动、卡顿和落点不准。

### 同名旧实例

电脑上同时存在 `/Applications/INbox.app` 和开发目录的 Debug 构建。现有脚本只按进程名称请求退出，并使用 `open -a INbox` 启动。macOS Launch Services 可能选择同名的开发构建，脚本也不能证明所有旧实例已经退出。

### 图标和退出入口

应用通过 `LSUIElement=true` 和 `.accessory` 隐藏 Dock 图标，又隐藏了窗口按钮。窗口一旦关闭，用户缺少稳定的重新显示和完全退出入口。

### 体积

Release App 约 37 MB，其中 FlutterMacOS framework 约 29 MB，App framework 约 7.5 MB；当前 DMG 压缩后约 17 MB。主要体积来自同时包含 Intel 与 Apple Silicon 的 Flutter 通用二进制，不是图片或业务资源。

## 方案选择

### 菜单栏入口

采用原生 `NSStatusItem`。菜单包含：

- 显示 INbox
- 检查更新
- 完全退出

不启用 Dock 图标，继续保持桌宠形态。点击红色关闭按钮只隐藏窗口，菜单栏图标仍在；“完全退出”终止进程。黄色最小化和绿色缩放保持系统提供的可用状态，不伪造自定义按钮。

没有选择持续显示 Dock 图标，因为用户已明确选择菜单栏图标。也不采用 Flutter 绘制的菜单栏替代物，因为它无法在窗口关闭后充当系统级入口。

### 平滑拖动

macOS 改用原生屏幕坐标计算：

1. Flutter 在拖动开始时通知原生层记录鼠标屏幕坐标和窗口原点。
2. 拖动更新时不再传递 Flutter 局部增量；原生层读取当前鼠标屏幕坐标，并根据“当前鼠标位置减起始鼠标位置”计算窗口绝对位置。
3. 拖动结束或取消时清理本次拖动状态。

这样窗口坐标系的移动不会反向污染下一次位移计算，通道消息延迟也不会累计成错误位置。Windows 暂时保留现有实现，本次只修复已复现的 macOS 问题。

没有采用逐帧节流，因为它只能减少卡顿，不能消除坐标反馈。没有直接调用 `NSWindow.performDrag(with:)`，因为 Flutter 的手势识别发生在原始 mouse-down 事件之后，容易影响单击采集行为。

### 应用内更新

更新只由用户从菜单栏选择“检查更新”触发，不做后台轮询，不在启动时自动联网，以维持本地优先和无后台网络请求的产品原则。

更新流程：

1. 原生菜单命令唤醒并显示 INbox 窗口。
2. Flutter 显示更新面板，并请求 GitHub 最新 Release 元数据。
3. 比较语义版本；当前版本已经是最新时给出明确提示。
4. 有新版本时，用户确认后下载固定名称的 macOS Universal DMG，界面显示字节进度、百分比和当前阶段。
5. 下载完成后校验 GitHub Release 提供的 SHA-256 digest；校验失败则停止，不替换应用。
6. 挂载 DMG，把新 App 复制到 `/Applications` 下的临时路径。
7. 启动一个随 App 打包的最小安装辅助脚本，传入旧进程 PID、暂存 App、正式 App 路径和备份路径。
8. INbox 正常退出。辅助脚本等待旧进程结束后，把现有 App 移到备份位置，再把新 App 原子移动到正式路径。
9. 替换成功后删除备份并通过完整路径打开 `/Applications/INbox.app`；失败则恢复备份并保留可读错误日志。

更新面板包含四种状态：检查中、可更新、下载/安装中、成功或失败。下载/安装期间禁用重复触发；失败不会删除当前可用版本。

GitHub 网络访问仅发生在用户主动检查或下载更新时。README 的“不联网”表述将同步改为“不后台联网；主动检查更新时仅访问 GitHub”。

### 一键安装脚本

终端脚本继续用于首次安装和恢复性安装，流程调整为：

1. 下载 DMG，并在终端显示进度。
2. 挂载并把新 App 复制到 `/Applications` 下的暂存路径。
3. 查找所有可执行路径以 `INbox.app/Contents/MacOS/INbox` 结尾的实例，包括开发目录构建。
4. 请求这些实例正常退出，并轮询确认；超时则停止安装并保留旧 App，不强杀、不边运行边覆盖。
5. 将旧 App 移到备份路径，再把暂存 App 原子移动到 `/Applications/INbox.app`。
6. 注册正式 App，删除备份，并用完整路径 `open /Applications/INbox.app` 启动。
7. 任一步失败都恢复旧 App，并输出清晰错误。

脚本不再使用先删除旧 App 再复制的方式，也不再使用可能选错副本的 `open -a INbox`。

### 版本与发布

- `pubspec.yaml` 版本改为 `1.1.1+2`。
- GitHub Release tag 使用 `v1.1.1`。
- Release 中同时上传带版本文件名和固定文件名的 Universal DMG。
- README 的 Latest 下载链接继续使用固定文件名，因此发布 `v1.1.1` 后无需再次修改链接。
- 发布前检查 App 内版本、Release tag 和 DMG 文件名一致。

## 体积策略

1.1.1 继续发布 Universal DMG。原因是 17 MB 已经是 Flutter Universal Release 的合理量级，现有脚本也使用最高级别 zlib 压缩；删除小资源不会带来可感知收益。拆分 arm64 和 x86_64 可以减少单次下载，但会增加两个构建、两个资产、架构判断和发布验证路径，当前收益不足以覆盖复杂度。

本次只移除能够证明未使用且不会改变 UI 的依赖或打包资源。若最终 DMG 没有显著缩小，则保留现状，不为了数字进行高风险裁剪。

## 组件边界

- `MainFlutterWindow.swift`：窗口按钮与原生拖动状态。
- `AppDelegate.swift`：菜单栏状态项和菜单命令分发。
- macOS MethodChannel：窗口显示、拖动生命周期、版本检查和安装阶段需要的原生能力。
- Flutter 更新 UI：状态呈现、确认操作和进度显示，不直接执行文件替换。
- 安装辅助脚本：只负责等待退出、原子替换、回滚和按完整路径重启。
- `scripts/install.sh`：首次安装及恢复性安装。

更新逻辑与采集、Vault 写入和像素动画保持隔离，不修改内容采集格式。

## 错误处理

- 无网络、GitHub 限流或 Release 缺少固定 DMG：显示错误，当前版本继续运行。
- SHA-256 不匹配：删除暂存下载，不挂载、不替换。
- `/Applications` 无写权限：停止更新，提示使用终端安装或手动授权。
- 旧进程未按时退出：不覆盖正在运行的 App。
- 新 App 暂存或移动失败：恢复备份。
- 新版本无法启动：保留安装日志和备份恢复路径，不声称升级成功。

## 测试与验证

### 自动化测试

- Dart widget 测试覆盖更新面板的四类状态和进度显示。
- Dart 测试覆盖拖动开始、更新、结束对应的平台调用，并保证拖动不触发采集。
- Swift 单元测试覆盖屏幕坐标到窗口原点的绝对位移计算。
- Swift 单元测试覆盖菜单命令映射以及显示窗口行为。
- Shell 测试用临时目录和假进程/命令覆盖成功替换、旧实例未退出、替换失败回滚和精确启动路径。
- 现有全部 Dart 测试、静态分析与 macOS Runner 测试保持通过。

### 手工验收

- 在不同方向和速度下拖动桌宠，窗口跟手且能停在指针目标位置。
- 红黄绿按钮可见；红色关闭后能从菜单栏重新显示。
- 菜单栏“完全退出”后活动监视器中不再存在 INbox 进程。
- 同时存在 Debug App 和 `/Applications` App 时，一键安装不会留下旧实例，且重启的是正式路径。
- 从旧版本主动升级到 1.1.1 时，App 内显示真实下载进度，完成后版本显示为 1.1.1。
- 断网、校验失败和替换失败均不会破坏当前安装。
- 发布资产的 SHA-256、架构、版本号和 Latest 下载链接经过发布后复核。

## 不在本次范围

- 自动后台检查更新。
- Apple Developer ID 签名、公证或 Sparkle 集成。
- Windows 自动更新。
- 改变采集格式、Vault 结构、桌宠视觉或动画。
- 为缩小体积拆分 Intel 与 Apple Silicon 安装包。
